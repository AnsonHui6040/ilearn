## 目的與範圍

把東海大學 iLearn（https://ilearn.thu.edu.tw，前端為 TronClass）本學期的作業、通知、課程資訊及課程檔案同步到使用者自己的機器，讓：

1. 任何 agent（Codex、Claude、Hermes 等）以固定格式知道有哪些工作未做、有哪些需要推送的通知；
2. 使用者隨時在本地取得課程檔案；
3. 使用者以終端機、桌面 app 或內聯網網頁查看資料及調整設定。

使用對象為東海大學學生（開發者本人及其他同學）。每位使用者各自安裝、各自登入，資料只存在自己的機器；不設集中伺服器代存他人帳密，不收集遙測。

不在範圍：代交作業、代答測驗、下載影片、修改 iLearn 上任何資料、繞過驗證碼或雙重驗證、直接發送 WhatsApp／Telegram 等訊息（由使用者自己的 agent 負責）。

## 架構

```text
            ┌────────────── 使用者機器（本機或 VPS）──────────────┐
iLearn ───► │ 同步核心 ─► SQLite ─► 規則引擎 ─► 推送佇列           │
(TronClass) │     │          │                   │                 │
            │     ▼          │                   ├─► outbox JSONL   │
            │  files/        │                   ├─► 本機指令 hook  │
            │                │                   └─► 本機 webhook   │
            │                ├─► 本地網頁伺服器（127.0.0.1）◄─ 桌面 app
            │                ├─► 文件夾 MD 檢視                    │
            │                └─► CLI --json ／ MCP server           │
            └──────────────────────────────▲──────────────────────────┘
                                           │ 接收推送／查詢／ack
                              Codex ／ Claude ／ Hermes 等 agent
```

- **單一核心**：同步、資料庫、完成判定、規則、推送全部在核心；CLI、網頁、桌面 app、MCP 只是外殼，不各自判斷狀態。
- **核心不呼叫 LLM**：分類用規則，不耗 token；摘要由使用者自己的 agent 產生後寫回。
- **建議技術**：TypeScript／Node.js 單一語言；CLI 用 checkbox prompt；網頁 UI 由核心內建伺服器提供，只綁 127.0.0.1；桌面 app 用 Electron 包同一 UI；MCP server 用官方 TypeScript SDK。此為建議，可改。

## 安裝流程

安裝完成後立即進入首次設定精靈（終端機為 `ilearn setup`，桌面 app 為首次開啟畫面），順序如下：

1. **偵測環境**：判斷為本機桌面或 VPS／雲端（無圖形介面、或使用者自選），決定預設介面及密碼提醒。
2. **輸入帳號密碼**：學號及密碼（不回顯），立即嘗試登入；失敗即顯示原因（密碼錯誤、需要驗證碼、網絡不通）並讓使用者重試。
3. **是否保存密碼**：按「登入與密碼」第 2 點處理；VPS 先顯示風險提醒。
4. **第一次完整提取**：登入成功後立即開始，抓取本學期全部課程、課程資訊、作業及繳交紀錄、影片進度、公告、分數，以及下載全部教材檔案。顯示進度（課程數、檔案數、已下載容量）；可中斷，下次從中斷處繼續。
5. **提取期間完成其餘設定**（不必等待下載完成）：介面啟用（終端機／文件夾／網頁／桌面 app）、推送方式、背景服務註冊、通知規則（直接採用預設亦可）、每科摘要剔選。
6. **完成摘要**：列出課程數、未完成作業數、3 日內截止及考試、下載結果及失敗項目。

首次提取的處理：

- 以首次提取的結果作為基線；首次提取本身不推送任何通知，只寫入 `sync.initial_completed`（`delivery: record`），供介面顯示「首次同步完成」。
- 使用者進入設定按「Reload」後才推送（見「Reload」）。
- 首次提取後至按 Reload 前，新出現的作業、公告及提醒照常推送；既有資料的提醒排程亦照常運作，3 小時強制推送不受影響。
- 首次提取未完成前，各介面標示「首次同步進行中」，不把未抓到的資料當作沒有作業。

## Reload

設定頁及終端機（`ilearn reload`）提供「Reload」：

1. 先立即同步一次（不等排程）；
2. 再把目前需要處理的事項逐則推送：未完成作業、未完成影片、7 日內考試、被退回的作業、本學期內等級為 `push` 以上的未讀公告及課程資訊變更、未讀的「有新分數」通知；
3. 已完成作業、已過的考試、`record` 等級的資料不推送；
4. 推送前顯示將推送的數量，使用者確認後才送出；
5. 這批事件帶相同 `reload_id`，類型沿用原有類型，另加 `"reason": "reload"`；agent 可據此合併成一則總覽；
6. 夜間按 Reload 屬使用者主動操作，即時推送，不保存到 07:00。

Reload 可重複使用（例如更換 agent 或重設推送方式後）；每次為新一批事件，不受之前已推送的 `dedupe_key` 限制，但同一批內不重複。

## 登入與密碼

1. **終端機登入（必備）**：安裝時由設定精靈完成；之後可用 `ilearn login` 重新登入（密碼不回顯）。桌面 app／網頁提供同一流程。
2. 登入成功後詢問「是否保存密碼以便過期自動重新登入？」：
   - 選否：只保存 session；過期時停止同步並推送 `auth.expired`，等待使用者重新登入。
   - 選是且為本機桌面：存入作業系統憑證庫（Windows Credential Manager／macOS Keychain）。
   - 選是且為 VPS／雲端：先顯示提醒——「伺服器被入侵或供應商可存取磁碟時，密碼可能外洩；加密金鑰亦在同一機器，只能防止一般誤讀」。使用者確認後才保存，檔案 0600。
3. `ilearn logout` 或設定頁可刪除 session 及已保存密碼；「更新權限」即重新登入。
4. 登入頁如有驗證碼或雙重驗證，自動重新登入不可行，一律走「選否」流程，不嘗試破解。
5. 密碼、cookie、token 不寫入 log、事件、MD 檢視，不經 CLI／MCP 輸出。

## 同步內容

| 類型 | 同步 | 本地下載 | 列待辦 | 完成條件 |
| --- | --- | --- | --- | --- |
| 作業（個人） | 是 | 附件 | 是 | 作業頁有繳交紀錄 |
| 作業（小組） | 是 | 附件 | 是 | 自己有繳交紀錄；或使用者標記「隊員已交」 |
| 影片 | 資料及進度 | 否 | 是 | iLearn 記錄進度 100% |
| 教材檔案 | 是 | 全部（本學期所有課程） | 否 | — |
| 老師公告 | 是 | 附件 | 否 | — |
| 考試／線上測驗 | 名稱、時間、地點、連結 | 否 | 否（只提醒） | 不追蹤；開始後停止提醒 |
| 問卷 | 名稱、時間、連結 | 否 | 否 | 不追蹤 |
| 分數、評語 | 是 | 否 | 否 | — |
| 課程資訊（上課時間、每堂資訊） | 是 | 附件 | 否 | — |

規則：

- **退回／重開**：已完成作業若顯示被退回或繳交紀錄被撤銷，重開並推送 `assignment.returned`。
- **可重交**：已有繳交紀錄後的重交、修改不產生事件。
- **小組作業**：自己未有繳交紀錄便與個人作業一樣提醒，即使系統顯示隊員已交。使用者在 UI／CLI 按「隊員已交」後才完成並停止通知；標記可撤回。偵測到隊員已交時，下一次提醒附註「系統顯示隊員已交，如屬實可標記」。Agent 不可代為標記。
- **考試日期**：iLearn 測驗／考試有明確時間的按該時間提醒。只出現在公告文字中的日期，解析到唯一日期才排提醒並標示「由公告推斷」；否則只推送公告本身。
- **截止日期更改**：保留舊值紀錄，重算提醒。
- **課程資訊變更**：比較「課程資訊」頁前後內容；上課時間、教室或某一堂資訊改動時產生 `course.info_changed`，並交規則引擎分類（例如命中「換教室」規則即推送）。
- **檔案版本**：以 content hash 判斷變更；老師更新同名檔案時舊版移入 `.versions/`。外部連結只記錄網址。
- **同步不完整**：任何課程抓取失敗即標示「資料可能不完整」並推送 `sync.incomplete`；不得把缺資料當作沒有作業，也不因此完成或重開。

## 同步與推送時間

時區固定 Asia/Taipei。

**同步**：07:00–24:00 每小時（07:00 至 00:00，共 18 次）；夜間 03:30 一次。每次加 0–5 分鐘隨機延遲，避免多位同學同時請求 iLearn。

**提醒計時器**：每 5 分鐘檢查一次，不依賴同步；發出前確認事項仍未完成／考試未開始。首次同步時已在提醒窗口內的，只發對應那一次，不補發已過的提醒。

**夜間保存（00:00–07:00，可改）**：

| 推送等級 | 夜間行為 | 預設用於 |
| --- | --- | --- |
| `force_push` | 即時推送 | 截止前 3 小時、考試前 3 小時 |
| `push` | 保存到 07:00 才推送 | 新作業、新公告、規則命中、退回、截止前 1 日等 |
| `record` | 不推送，只記錄供查詢 | 未命中推送規則的公告、新教材等 |

07:00 釋放時：若同一事項的 3 小時提醒已在夜間強制推送，對應的 1 日提醒不再送出；同一事項多則保存事件可合併為一則。

背景執行：VPS 用 systemd timer 或 cron；Windows 用工作排程器；macOS 用 launchd。安裝時選擇是否註冊背景服務，桌面 app 關閉後仍按排程運作。

## 關鍵詞觸發規則

規則引擎決定每則公告／課程資訊變更屬哪類及推送等級。全部規則可在 UI 或設定檔中新增、修改、停用；內建規則只作預設值。

規則格式（`rules.yaml`）：

```yaml
- id: room_change
  name: 更換教室
  enabled: true
  scope: all              # all，或課程 ID 清單
  fields: [title, body, course_info_diff]
  any:  [更換教室, 教室異動, 改至, 移至, 地點變更, room change]
  all:  []                # 全部需同時出現
  none: []                # 出現任何一個即不命中
  regex: []               # 進階用，可留空
  action: push            # force_push ／ push ／ record

- id: exam
  name: 考試／測驗
  enabled: true
  scope: all
  fields: [title, body]
  any:  [考試, 期中考, 期末考, 小考, 隨堂測驗, 測驗, exam, midterm, final, quiz]
  none: [成績, 分數, 公布, 檢討, grade, score]
  action: push
```

判定邏輯：

1. 規則條件為 `any`（至少一個）且 `all`（全部）且非 `none`（排除）；`regex` 與 `any` 同為「或」。
2. 一則可命中多條規則；分類取全部命中規則，推送等級取最高（`force_push` > `push` > `record`）。
3. 沒有命中任何規則：歸「一般通知」，`record`。
4. 每科可覆寫規則的啟用與等級。
5. **試算**：儲存規則前，UI／CLI 列出最近公告中會命中及不再命中的項目，讓使用者確認效果。
6. 使用者可對單則公告手動改分類；手動結果優先於規則，不影響其他公告。

內建預設規則：

| 代碼 | 類別 | 預設等級 | 主要關鍵詞 | 排除詞 |
| --- | --- | --- | --- | --- |
| `exam` | 考試／測驗 | push | 考試、期中考、期末考、小考、測驗、exam、quiz | 成績、分數、公布、檢討 |
| `deadline` | 繳交／截止 | push | 繳交、截止、期限、最後一天、上傳、due、deadline | — |
| `deadline_change` | 截止延長／提前 | push | 延期、延長、展延、提前、改期、extended | — |
| `class_cancel` | 停課／調課／補課 | push | 停課、休課、調課、補課、不上課、取消上課、颱風假、放假 | — |
| `room_change` | 更換教室 | push | 更換教室、教室異動、改至、移至、地點變更 | — |
| `online_class` | 改線上上課 | push | 線上上課、遠距、視訊、Google Meet、Teams、Webex、直播 | — |
| `presentation` | 報告／分組 | push | 報告、簡報、上台、分組、組別 | 成績 |
| `attendance` | 點名／出席 | push | 點名、出席、請假、缺席 | — |
| `syllabus_change` | 大綱／進度變更 | push | 課程大綱、進度調整、評分方式、配分 | — |
| `grade_release` | 成績相關公告 | record | 成績、分數、公布成績、grade、score | — |
| `event` | 演講／參訪 | record | 演講、講座、參訪、校外教學、工作坊 | — |
| `material` | 新教材 | record | 講義、投影片、教材、slides | — |
| `survey` | 問卷 | record | 問卷、調查、教學評量 | — |

例：「上次考試成績已公布」命中 `grade_release`，被 `exam` 的排除詞排除，結果為 `record`，公告本身不推送；若 iLearn 同時出現新分數，則由 `grade.posted` 通知「有新分數」。使用者問 agent 時，agent 可查到此公告及分數。

規則只影響分類及推送，不改變作業完成狀態；考試提醒只由 iLearn 測驗時間或公告中解析到的唯一日期觸發。

## 推送給 agent 的格式

核心把需要推送的事件經三種方式交給 agent，內容相同，使用者在設定中選用：

1. **outbox 檔案（預設，必備）**：agent 定時讀取；
2. **本機指令 hook**：每則可推送事件執行使用者設定的指令，事件 JSON 經 stdin 傳入（例如呼叫某 agent 的 CLI）；
3. **本機 webhook**：POST 到使用者設定的 localhost 位址。

hook／webhook 失敗時重試，outbox 仍保留，不會遺失。

```text
<資料根>/outbox/
├── events/2026-10-22.jsonl      # 每行一個事件，只追加
├── cursors/<agent名稱>.json     # 每個 agent 已處理到哪個 event_id
├── schema/event.v1.json         # JSON Schema
└── 通知.md                      # 人可讀檢視
```

事件格式（v1）：

```json
{
  "schema": "thu-ilearn.event.v1",
  "event_id": "01JB8X5Q4N3Z...",
  "type": "announcement.new",
  "detected_at": "2026-10-22T01:12:40+08:00",
  "deliver_after": "2026-10-22T07:00:00+08:00",
  "delivery": "push",
  "categories": ["room_change"],
  "matched_rules": ["room_change"],
  "course": { "id": "12345", "name": "資料結構", "semester": "114-1" },
  "item": {
    "id": "88001",
    "kind": "announcement",
    "title": "下週起改至 M201 上課",
    "due_at": null,
    "url": "https://ilearn.thu.edu.tw/course/12345/..."
  },
  "summary": null,
  "dedupe_key": "announcement.new:88001"
}
```

`type` 固定清單：`assignment.new`、`assignment.due_reminder`（帶 `offset`，如 `P1D`、`PT3H`）、`assignment.returned`、`exam.new`、`exam.reminder`（帶 `offset`）、`video.new`、`announcement.new`、`material.new`、`survey.new`、`course.info_changed`、`grade.posted`、`feedback.posted`、`auth.expired`、`sync.incomplete`、`sync.initial_completed`。

規則：

- `delivery` 為 `record` 的事件只寫入 outbox 供查詢，hook／webhook 不觸發。
- agent 只應送出 `deliver_after` 已到的事件；`events --deliverable` 只回傳這些。
- `grade.posted`／`feedback.posted` 等級為 `push`，只說明哪一科、哪一項有新分數／評語，不含分數或評語內容。
- `summary` 只在該科啟用摘要且 agent 已寫回時才有內容。
- 同一 `dedupe_key` 只推送一次（Reload 批次除外，以 `reload_id` 區分）；各 agent 各自 cursor。
- 新增欄位向後相容；破壞性改動升級為 v2，並保留 v1 輸出一段過渡期。

## Agent 查詢介面

1. **CLI JSON**（任何能用終端機的 agent）：`ilearn tasks --json`、`ilearn events --deliverable --agent <名稱> --json`、`ilearn events ack <名稱> <event_id>`、`ilearn courses --json`、`ilearn course <id> --json`、`ilearn announcements --category <代碼> --json`、`ilearn grades [--course <id>] --json`、`ilearn files search <關鍵字>`、`ilearn file text <id>`、`ilearn summaries pending --json`、`ilearn summaries put <id>`。
2. **MCP server**：同一組工具，供支援 MCP 的客戶端使用。
3. **說明檔**：隨附 `AGENTS.md` 及 `SKILL.md`，說明用法、事件格式及限制，讓 Codex、Claude、Hermes 等直接使用。

Agent 權限：

- 可以：讀取所有同步資料（包括分數及評語，用於回答使用者提問）、ack 事件、寫回摘要。
- 不可以：改完成狀態、標記「隊員已交」、改規則、讀帳密、觸發登入。
- 分數：系統只負責保存及顯示，推送只通知「有新分數」；使用者問 agent 時，由 agent 經 `ilearn grades` 讀取並回答。

## 摘要設定

- 每科兩個獨立剔選：「教材檔案摘要」、「老師公告摘要」；未剔選即只顯示標題。預設全部不剔選。
- 已剔選課程的新內容進入 `summaries pending` 佇列；agent 讀取、摘要、寫回並記錄來源 hash；內容未變不重新摘要。
- 可設每日摘要數量上限，控制 token 用量。

## 介面

第 5 版起，以下各頁改由終端機全螢幕介面提供，分頁、按鍵與顯示規則以 `docs/plans/2026-10-23-phase4-web-ui-audit.md` 第 9 節為準；本節其餘文字保留為原始需求。

**首頁（總覽）**：本週課程時間表（取自各科「課程資訊」）＋重要通知（3 日內截止或考試、被退回、推送等級為 push 以上的公告、登入過期／同步不完整）。點擊課程進入該科課程頁。

**課程頁（每科一頁）**：上課時間及每一堂資訊、待辦（按截止日，逾期另列；小組作業附「隊員已交」按鈕）、已完成、考試、老師公告（附分類標籤，可改分類）、教材檔案（可直接開啟本地檔）、問卷、影片進度、分數及評語；每項附「在 iLearn 開啟」連結。

**保留頁**：學期結束後整學期移入，如「114-2」一頁，內有該學期各課程頁；停止提醒，檔案保留。

**設定**：Reload 按鈕、帳號與權限、介面啟用、推送方式（outbox／hook／webhook）、夜間時段、提醒時間、關鍵詞規則（新增、修改、試算、停用）、每科覆寫（摘要、規則、提醒）、同步狀態及最近錯誤。

**終端機**：所有設定均可經 `ilearn setup` 互動完成（方向鍵、空白鍵剔選、Enter 確認），規則亦可直接編輯 `rules.yaml`。

**文件夾模式（VPS）**：

```text
<資料根>/
├── config.yaml
├── rules.yaml
├── 總覽.md
├── 課程/資料結構.md …
├── 保留/114-2/…
├── files/114-1/資料結構/<分類>/<檔名>
├── outbox/…
└── data/ilearn.sqlite3
```

目錄 0700、檔案 0600；MD 為唯讀檢視，手動修改不影響狀態。網頁伺服器只綁 127.0.0.1；在 VPS 上要遠端開網頁，建議經 SSH tunnel 或 Tailscale，不直接對公網開放。

## 風險

- **非公開 API**：TronClass 未見公開開發者文件，同步依賴網頁內部 API；改版即可能失效。須偵測並推送 `sync.incomplete`，不可靜默出錯；發布後需有人維護。
- **學校規範**：自動存取可能受學校資訊使用規範限制；發布前應查閱，同步頻率保持在上述範圍。
- **帳號安全**：同學需信任此程式處理學校帳密；開源、不收集遙測、密碼預設不保存。
- **判定錯誤**：誤判已完成會令使用者漏交；繳交紀錄核實失敗一律保持未完成。關鍵詞誤判只影響推送，不影響完成狀態。

## 驗收條件

1. 有繳交紀錄才完成；只有列表標記而核實失敗時保持未完成。
2. 退回會重開並推送一次；可重交作業重交不產生事件。
3. 小組作業在自己未交時持續提醒，即使隊員已交；標記「隊員已交」後停止，撤回後恢復；agent 無法標記。
4. 影片 100% 才完成；考試及問卷不出現在待辦。
5. 作業及考試提醒在前 1 日及 3 小時各一次（容許 5 分鐘誤差）；已完成作業、已開始考試不提醒；改設定即生效。
6. 夜間：push 事件在 07:00 前不會被 agent 取得；3 小時提醒在夜間即時推送；已在夜間發出 3 小時提醒的事項，07:00 不再送 1 日提醒。
7. 規則：「更換教室」公告即推送；「上次考試成績已公布」不推送但 agent 可查到；新增、修改、停用規則及每科覆寫即時生效；試算結果與實際一致。
8. 有新分數時推送一則通知且不含分數或評語；課程頁顯示分數；agent 經 `ilearn grades` 可讀分數。
9. 同一事件不重複推送；不同 agent 的 cursor 互不影響；hook／webhook 失敗後重試，outbox 不遺失。
10. 拒絕保存密碼時沒有任何密碼落地；VPS 選保存前必定顯示提醒。
11. 同步失敗不會令任何作業消失或變成完成。
12. 學期切換後舊學期進入保留頁並停止提醒，檔案仍可開啟。
13. 網頁伺服器只監聽 127.0.0.1（第 5 版起不提供網頁伺服器，此項不適用）；帳密不出現在任何 log、事件或 agent 輸出。
14. 安裝後設定精靈即要求帳號密碼並完成第一次完整提取；中斷後可續傳；首次提取不推送任何通知；提取未完成前各介面標示進行中。
15. 按 Reload 先同步，再顯示數量並經確認後推送全部未完成／即將發生事項；已完成項目不推送；重複按 Reload 會再推送一批，同批內不重複；夜間 Reload 即時推送。
