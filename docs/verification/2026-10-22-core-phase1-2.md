## 代使用者做的決定

| 決定 | 原因 | 如果錯的代價 |
| --- | --- | --- |
| 子代理不 commit，由主控驗證後 commit | 使用者守則 | 無 |
| 第 2 波 6 個子代理並行（檔案不重疊） | 使用者要求多個 Sonnet 子代理 | 無 |
| 每個 Task 及最後審查由主控親自做，沒有另派 reviewer 子代理 | 使用者指定主控只負責檢查及統整 | 少一層獨立審查 |
| 所有依賴在 Task 1 一次安裝 | 避免多個子代理同時改 package.json | 無 |
| 夜間計算移到 Task 1 | Task 7 依賴它 | 無 |
| 項目 id 加類別前綴（如 `assignment:1741182`） | iLearn 不同類資料的 id 可能重複 | agent 看到的 id 格式含前綴 |
| 沒有任何關鍵詞的規則不命中 | 避免一條空規則推送所有公告 | 無 |
| 課程資訊變更以「教室異動：M134 → M201」等字樣交規則引擎 | 讓更換教室規則可以命中課表變更 | 字樣固定在程式內 |
| 23:59 的 push 即時送出（計劃原文寫錯） | 設計書夜間為 00:00–07:00 | 無 |
| 夜間的 1 日提醒保留到 07:00 後的第一次檢查才送；3 小時提醒已送則不再送 | outbox 只追加，無法事後收回 | 1 日提醒最遲約 07:05 送出 |
| Reload 推送全部符合條件的項目，不分已讀未讀 | 本階段沒有已讀紀錄 | 可能重推 agent 已處理的公告 |
| Reload 對所有已公布分數的項目送 `grade.posted` | 設計書未限制只送學期總分 | Reload 批次較長 |
| 登入過期：有保存密碼自動重新登入一次，否則推送 `auth.expired` | 設計書「登入與密碼」 | 無 |
| 學號存在 `<資料根>/data/account.json`（0600） | 設定檔沒有對應欄位 | 多一個檔案 |
| 老師關閉下載的檔案預設略過 | 使用者決定（可在 config 改） | — |

## 已知小問題（延後）

- 1 日提醒的取代判斷只認得預設 offset（P1D、PT3H）及當次清單內的 offset；自訂其他 offset 時可能重複提醒。
- hook 失敗沒有逐步延長重試間隔（hook 投遞本身在 Phase 3）。
- `setup` 的 Ctrl-C 要等目前那一個 API 請求或檔案下載完成才停。
- 每科摘要設定要等首次提取抓到課程列表後才問。
